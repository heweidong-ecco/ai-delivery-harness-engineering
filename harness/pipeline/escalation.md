# 升级上报机制

## 触发条件

| 条件               | 升级到     |
| ------------------ | ---------- |
| 需求评审超过 3 轮  | 需求负责人 |
| 编码评审超过 2 轮  | 技术负责人 |
| 单测评审超过 2 轮  | 技术负责人 |
| CI 连续失败 3 次   | CI Owner   |
| 部署验证失败 2 次  | 运维负责人 |
| Agent 试图跳过评审 | 流程 Owner |
| 安全规则违规       | 安全负责人 |
| 数据规则违规       | 数据负责人 |

## 上报格式

| 字段     | 内容     |
| -------- | -------- |
| 需求编号 | REQ-XXXX |
| 阶段     | <阶段>   |
| 问题     | <问题>   |
| 已尝试   | <尝试>   |
| 建议     | <建议>   |
| 升级对象 | <角色>   |

## 记录

写入 `harness/changes/REQ-XXXX/escalation.md`。

## 硬性约束

- 升级必须留痕。
- 升级必须有人接手。
- 升级后 Agent 暂停。
